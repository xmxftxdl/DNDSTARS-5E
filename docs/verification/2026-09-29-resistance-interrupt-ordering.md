# 抗性中断顺序核查

本记录区分已修复的行为与尚需修复的同类问题，不认证任何完整原书条目。

## 已确认及修复

`damageMitigationInterrupt.test.ts` 新增已有火焰抗性再使用抗性反应的实际攻击回归。原实现把普通抗性结算后的4点再次减半：30 HP受到9点火焰伤害后剩28，正确应剩26。原失败日志：`.codex-logs/damage-mitigation-resistance-gap-20260929.txt`。

`applyDnd5eDeclaredDamageMitigationInterrupts` 现在使用当前目标及伤害来源重新检查已有抗性，若全部当前伤害类型已经具备抗性/免疫，不重复减半。消耗已声明反应仍由现有事务处理。实际回归现已通过，普通伤害类型、魔法性等来源条件仍交给统一防御计算器。

## 未解决：逐类型及原始伤害顺序

代码检查显示该函数仍在 `applyDamageInternal` 中处理已合计且经过防御的 `amount`；resistance分支只检查 `damageTypes` 是否与允许列表有交集，随后将整个amount减半。这不能证明混合伤害只减半受保护的分量；混合既有抗性也不能用“全部已抗性”判定代替逐分量处理。类型抗性被压制、易伤与奇数取整组合亦需要从原始类型分量重新验证。

不要将 resistance 简单改成整个伤害包乘倍率，也不要用已经合并的最终数值猜回原始伤害。需要将声明式抗性合并到各原始类型分量的统一防御阶段，同时保证反应/资源只消耗一次、同一次攻击内各分量适用、之后的攻击不继承，并复用原有原子回滚。

下一批关键入口：

- `resolveDamageDefensesForTarget`：实际统一防御、抗性压制及抗性先取整后易伤。
- `adjustDnd5eDamageComponents` 与 `adjustDamageForTarget`：多类型与单类型路径。
- `visitDnd5eRawDamageCheckpoint`：只覆盖部分路径，且受监听器门槛控制，不能只在这里加中断就声称全部路径完成。
- `applyDnd5eDeclaredDamageMitigationInterrupts`：完整来源资格、范围、资源与已激活追踪，可复用但不能继续在最终总值上减半。
- `resolveDnd5ePostD20AttackAdjustment` 与最终事务清理：已有攻击专属临时抗性生命周期可供参考；多重攻击不能继承前一次攻击的抗性。

“灵体防御”诊断仍未审定为可表达。多类型、免疫/易伤/压制、内置与Activity伤害、后续攻击、拒绝/重放/零伤害等行为必须补充真实Host回归。当前尚未运行这些新矩阵，不能把代码推导说成已验证结果。
