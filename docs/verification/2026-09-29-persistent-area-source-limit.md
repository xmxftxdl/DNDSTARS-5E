# 持续区域的来源数量限制

`create-persistent-area.sourceLimit` 使用 `{groupId, maximum}`。同一模块的不同 Activity 模式使用同一个 groupId，即可共享来源上限。maximum 为 1–64 的整数，未知字段及无效 ID 拒绝。没有该字段的旧区域保持原行为。

地图提交需要 Host 提供完整 `sourceLimitMaps`；当前事务地图替代集合中的旧版本。角色按持久角色 ID 跨地图统计，非角色 Token 按所在地图及 Token ID 隔离。模块 ID 和 groupId 均相同才合并；已有更严格上限时采用较小值。一次提交多个创建操作时逐个计入暂存地图，任一步超限都不返回可提交地图，也不修改输入。

存档保留限制组。世界时间已到期的区域不占数量；缺少可比时间时保守保留其他地图区域，不能拿当前地图回合数判定另一地图过期。永久区域持续占用；实际解除后释放。即时操作不创建持续区域，因此不占该接口的名额。接口不会自动删除最旧效果，原文若要求替换或先选择解除，应另行表达对应流程。

合成测试覆盖导出读取及执行器传递、不同地图中的同一来源、其他来源/组隔离、JSON重载、到期、已授权解除、重复同一handoff、缺少Host快照、非法声明及同事务三次创建超限的原子拒绝。原有区域/解除/迁移/校验/执行器6文件263项回归通过；新增归档和批次用例3项单独通过（与前者重叠，不相加）。

这不是操水整项认证：原文水体资格、冻结时生物检测、具体区域表现及动作解除完整玩家交互仍需原来源配置和隔离双端验收。并发房间写入与全书重生成也未由本测试证明。完整类型检查结果见主进度日志。
