## 已核实的缺口

全书 backlog r14 / review r23 中，幽魂凝视诊断 `205cd92aa2638498e83e6448d703dbe70b7282d66b316f7be6a57779ac633c0c` 要求仅在缺少黑暗视觉时授予范围；幽域追踪者诊断 `0683fad9266b94dcace5cc3fbdba908baad8b2529fdae7bba799138158ea0cd0` 同时包含已有范围延长，以及观察者依赖黑暗视觉时的相对隐形。

当前实现只支持无条件范围取最大值：

- `plugins/pluginMechanicsContracts.ts` 的静态字段是 `darkvisionRangeFeet`。
- `activities/dnd5eEffectContracts.ts` 的修正是 `darkvision { rangeFeet }`。
- `activities/dnd5ePermanentContentEffects.ts` 将永久修正投影为最大范围。
- `character.ts` 合并所选规则的静态最大范围。
- `shared/dnd5e-vision-profile.mjs` 对 Token、自定义角色投影、怪物感官及未暂停的临时效果取最大范围。
- `headlessCombatEngine.ts` 的 `dnd5eEffectiveDarkvisionRangeFeet` 另合并基础范围和活动效果。

因此无条件授予30尺不能代替“没有才授予30尺”：已有15尺的自定义感官会被错误提高。固定授予60尺也不能代替“已有60尺则再增加30尺”。这些是代码行为推导，尚未提交新增实现或行为认证。

## 下一批实现与验收边界

1. 在共享视野合并阶段表达“无既有感官时授予”与“已有感官时增加”，输入应先包含永久、临时和怪物基础感官；不要把最终结果提前固化到角色快照后再次加成。
2. Native Effect、永久投影、插件校验、角色/Token/Headless快照、共享渲染与服务器投影必须使用同一语义。需要检查 Token 与角色重复携带同一来源时的去重，不能重复增加范围。
3. 临时效果结束、反魔法暂停、重新加载、变形保留/替换规则均需验收。普通黑暗视觉不能因此看穿魔法黑暗。
4. 对观察者的相对隐形是独立机制；不能因范围分支实现而移除整个幽域追踪者复合诊断。
5. 合成归档测试覆盖无范围、0、短于默认范围、长范围、已有感官加值、来源撤销、临时变化与多来源。原始条目仍需集中转换和来源行为验收。

### 原文复核补充

阴影视野的已有范围加值限定于种族特性提供的黑暗视觉。当前通用existingBonusFeet合并所有已有感官后加值，因此不能当作该条款完成：种族60尺与临时120尺同时存在时，应比较种族增强结果90尺与临时120尺，得到120尺，不能得到150尺。下一批须新增来源限定及回归，相对观察者隐形仍独立待实现。

### 种族来源范围分支已实现

新增 Native Effect 的 `existingRangeSource: 'race'`，必须同时声明 `ifAbsent: true`。种族基准由核心种族或插件种族静态范围产生，与所选非种族特性及临时效果分离。永久与临时修正均支持该分支；先计算种族增强范围（或无种族感官时的授予范围），再与其他感官取最大值。角色、Headless、地图 Token、投影缓存和归档校验均接入该语义。

合成归档经过两次导出/导入，分别验证无种族视觉和矮人种族视觉；独立 Host 测试提交临时来源限定效果。种族 60 + 增强 30 + 临时 120 最终为 120；种族 120 + 增强 30 + 临时 120 最终为 150。移除条件效果恢复 120，移除临时普通视觉恢复种族增强结果。投影 JSON 重载不重复加值。

### 逐观察者隐形接口已实现（来源行为认证仍未完成）

新增原生 `darkvision-concealment`，贯通永久特性投影和临时机械 Effect、归档注册、严格重载、角色/地图同步。共享谓词区分目标处于黑暗、观察者依赖黑暗视觉和替代感官。Host 复用方向性感知判定，影响攻击的未见优势/劣势；服务器用目标光照及每名观察者的范围决定是否保留身份，不添加全局隐形条件。
