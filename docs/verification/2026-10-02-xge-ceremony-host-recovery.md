# 典礼术：DM 刷新后的旧请求恢复

## 问题与修改

真实玩家施放成人礼，在 DM 资格确认尚未结束时刷新 DM，原请求没有完成回执，玩家一直等待。持久化的施法过程标记也仍存在。

规则准备入口现在拒绝为同一个已经开始的请求重新创建连续性凭据，返回 `casting-continuity-lost`。序列化的过程标记不能证明 Host 离线期间施法未中断；新用户请求仍允许正常准备。

恢复拒绝分支清理对应请求的过程专注，并持久化后发布拒绝回执。初次修复用房间命令清理，实际测试证实该等待卡住；现改为在正在持有权威事务的分支内创建并应用规则计划，避免嵌套等待房间命令。计划严格匹配请求、法术、地图、Token、角色与当前专注 ID，不清理其他请求或替换后的专注。

玩家收到明确的施法中断提示。临时诊断日志已从生产代码移除。
