# PDF 法术批量草稿导入

入口：DM 工坊 → PDF 法术批量转换。

上传 PDF 后先在本地提取文本；点击“开始／继续转换”才调用现有 AI Credit 通道。
当前通道沿用项目模型策略，不在此功能中偷偷更换模型或密钥。未执行真实付费请求。

## 当前流程

1. 全页提取；存在未解决的 OCR 缺页时拒绝建立整书批次。
2. 每两页建立提取任务，附带后续两页供跨页补全。起始页拥有权避免相邻任务重复提取。
3. AI 返回逐法术原文、页码和提取警告。Host 核对页码、标题、连续原文证据及重复条目。
4. 清单扫描结束后，逐法术调用现有结构化转换器和内容包校验器。
5. 展示原文、页码、接口覆盖、假设和不支持机制。载入工坊校对后使用原有保存／启用流程。

批次按房间保存到浏览器。每完成一项保存一次，暂停在当前请求结束后生效；失败项保留错误，下次继续重试。
每轮默认最多 10 项，允许调整至 1–100；这不是积分上限，转换器内部重试也可能计费。
JSON 草稿导出包含原文和进度，仅供用户本地保存，不自动上传市场或共享给房间。

## 验收边界

- 本轮没有收到扩展 PDF，因此没有核对珊娜萨实际法术总数，也没有声称整本已完成转换。
- 来源字符串匹配只能验证证据存在，不能证明 AI 没有遗漏法术、遗漏正文尾部或错误理解规则。
- 超过后续两页的长条目、双栏顺序混乱、图像版资料会需要进一步处理；警告不能当作成功。
- 接口覆盖报告不等同于行为测试通过。法术的命中、豁免、升环、专注、到期、叠加、回合触发与玩家／DM 一致性仍需逐机制测试。
- 既有未实现的嵌入武器攻击等机制不会因导入而自动获得实现；必须列为缺口。
- 当前是批量生成草稿、逐项工坊导入，不是未经校对的整书一键启用。

测试使用自造法术原文，不附带商业扩展书籍内容。

## 使用真实资料验收

1. 上传用户自己的 PDF，核对页数与 OCR 缺页提示。
2. 完成提取后，将识别清单与书中法术目录核对；逐条检查跨页尾段与升环说明，不能仅靠识别数量判断完整。
3. 逐条打开草稿，核对目标、施法资源、伤害类型、豁免成功分支、等级缩放、持续时间及触发条件。
4. 对缺口按机制归类，先扩展通用接口并编写确定骰值的 Host 测试，再重新生成受影响的草稿。
5. 玩家与 DM 双端测试申请／拒绝、合法目标、落点、状态同步与资源扣除；重复提交不能重复结算。
6. 保存通过验收的草稿；保留未通过项和其原因。不能以 AI 声称支持或格式校验通过替代上述验收。
