# DM 优势/劣势补骰动画

修复确认窗口暂停普通动画队列导致补骰先显示结果、等待后续投掷才播放的问题。

- 补骰使用专门的追加请求，允许在当前 DM 确认窗口内立即播放；其他普通请求仍保持暂停。
- 主端生成一次点数，将原骰与新骰、追加位置和模式一起发送给对应玩家。沿用玩家归属过滤；暗骰不广播。
- 底层使用 `dice-box-threejs.add()`，原骰在预演和播放期间保持静止，只投新增骰子；iframe 不随追加数量变化重载。
- 补骰完成后才更新确认窗口与判定；播放期间禁用模式、骰面编辑与确认。已有两枚骰子后切换模式不重复投掷。

## 验证

四个相关测试文件 25 项通过。生产 Vite 构建通过。

浏览器打开独立 DM/玩家双页 `e2e/fixtures/dm-supplement.html`，使用真实生产骰盘组件、动画队列及 WebGL 引擎。页面间通过 BroadcastChannel 发送同一请求，测试补骰固定为 18：

1. 原骰为 6，点击 DM 优势一次。
2. DM 确认按钮立即禁用，玩家直接显示投掷中，无需点击投掷。
3. 两端动画完成计数均为 1，骰面均为 6、18；玩家显示优势并标记采用 18。
4. iframe 在补骰前后保持相同 URL、相同 AX 节点，未重载。
5. DM 切换劣势后完成计数仍为 1，确认成功，采用 6。

此双页测试验证真实动画与请求处理，不等同于 5273/5274 实际房间网络、权限及完整攻击结算的端到端测试。
