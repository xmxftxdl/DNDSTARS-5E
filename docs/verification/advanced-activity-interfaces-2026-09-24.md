## 使用说明

- `continuation.maximumSteps` 包含第一段，范围 2–64；当前续接限定在同一先攻回合内。`when` 可要求指定检定成功或某组骰子的两个面值相等。`carryRolls` 映射原始 Host 骰值；声明式导入器自动为下一段填写 `carriedRollIds`。直接编写原生 Activity 时需声明这个数组。
- 每一段仍独立验证自身射程、目标和资源。`maximumDistanceFromPreviousTargetFeet` 另行约束相邻目标距离。需要超出原施法射程的连锁时，后续 Activity 的自身范围也应相应声明，不能只改续接距离。
- 后续动作通常声明 `activation: { kind: "free" }`，不重复消耗法术位。Host 保存 castLevel；客户端不能在续接中改环级。
- B2 的 `maximumAmount` 是本次事务的总减免/转移上限。transfer 转移的是已结算伤害，不再对承伤者重复计算抗性；需要别的伤害顺序时，不能把此模式当作等价实现。
- 库存附魔对实物绑定，转交保留原实例；被绑定的库存堆不能拆成多个实例复制效果。旧的无库存实例装备继续沿用原有装备 ID 兼容路径。弹药/充能使用现有物品资源消耗，不把角色资源冒充物品资源。
- `targetFormIds` 是注册命令中的目标 ID → 已声明形态 ID 映射；原生插件载荷字段为 `activityTargetFormIds`。未覆盖的目标使用公共形态选择。目前普通选择弹窗仍提供公共形态；逐目标配置可通过接口传入。
- 保留生命值模式在形态期间拒绝其他临时生命值授予；形态结束同时清除其临时生命值。原生引擎、房间结束专注和服务端同步都处理恢复。
- 召唤/变形必须引用已安装的真实怪物数据；这些接口不会补造缺失的数据，也不对 DM 的叙事判断自动作决定。

## 原创导入示例

`examples/activity-advanced.json` 可从本地 JSON 导入。它是用于演示条件续接和保存骰值的原创测试特性，不对应某个扩展法术的完整规则。

## 验收与边界

验收包含新接口、原生插件结算、库存流转、Activity 回归、房间命令、变形旧规则和召唤地图处理。通用机制通过测试不等于某一扩展的每个法术都已转录正确；例如随机伤害类型选择、特殊承伤顺序、召唤失控后的具体行为，仍需在各法术包中配置并逐项验收。

项目原有 architecture 审计超限仍存在，本次未放宽预算；生产产物使用单独 Vite 构建验证。
