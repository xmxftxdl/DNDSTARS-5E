# 地图图片墙体识别基准（2026-07-24）

## 结论

当前识别器的性能足够用于交互预览，但准确率不足以自动写入权威地图几何：

- 13 张公开地图的单图中位耗时为 `222.4 ms`，最大单次耗时为 `846.2 ms`。
- 10 张带 UVTT 真值的地图按线长加权后，Precision 为 `0.95%`、Recall 为 `10.10%`、F1 为 `1.74%`。
- 简单、边界清晰的地图可达到 `40.5% F1`，纹理复杂地图会产生大量装饰线误报，部分地图的墙体也没有直接画成深色线。
- 两张黑线白底扫描图的候选肉眼可用，规则网格过滤有效；一张白线黑底扫描图返回 0 条候选，说明算法目前不支持反色图。
- UVTT/DD2VTT 自带的 `line_of_sight` 应始终优先直接导入；图片识别只能作为没有矢量数据时的 DM 辅助，并继续要求人工确认。

本次真实文件还发现 DungeonDraft 通常把内嵌图片写成裸 Base64，而不是 Data URL。导入器已经增加 PNG、JPEG 和 WebP 裸 Base64 兼容。

## 方法

- 使用生产代码 `detectWallsFromImageFile`，在 Chromium Web Worker 中运行。
- 默认参数：暗度阈值 `68`、最短线比例 `0.025`、分析最长边 `1600 px`。
- 每张地图运行 3 次，报告中位耗时。
- UVTT 真值取 `line_of_sight + objects_line_of_sight`，按 `map_origin`、`map_size` 和 `pixels_per_grid` 映射到实际图片。
- 沿预测线和真值线等距采样；采样点落在另一组线段容差范围内即视为命中。该方法按线长加权，不会因一条墙被拆成多段而人为降分。
- 扫描图没有矢量真值，因此只记录候选数量、耗时和人工叠加层判读，不给出虚假的像素级 F1。

## 参数扫描

对暗度阈值 `24/40/56/68` 与最短线比例 `0.05/0.10` 做了全语料扫描。最佳加权 F1 为暗度 `56`、最短线 `0.05` 时的 `1.81%`，但 Recall 从默认值的 `10.10%` 降至 `5.51%`。这不是足以替换默认值的改进。

## 环境与复现

- Windows，AMD Ryzen 7 3800X（8 核／16 线程），47.9 GB RAM。
- Node.js `v24.16.0`，Playwright `1.61.1`。
- 命令：

```powershell
node scripts/map-image-benchmark.mjs `
  --corpus C:\path\to\benchmark-maps `
  --output map-image-benchmark.json `
  --overlays map-image-overlays `
  --runs 3
```

可用 `--darkness-threshold` 和 `--minimum-run-ratio` 重跑参数组合。

## 下一步建议

1. 增加黑白极性自动判断，先解决白线黑底的 0 候选问题。
2. 对彩色地图做墙体语义分割或边缘配对，避免把地板、家具和阴影当作墙。
3. 使用 UVTT 矢量真值训练／调参，并按地图风格选择识别配置。
4. 在准确率达到可接受水平前，保留候选预览、逐条删除和 DM 明确确认。
