# 社区模块迁移与验收

## 基线与架构

迁移前工作已提交并通过 PR #9 合并至 `main`，基线为 `e67780513cedcd01aa7c886ad8286d48e0e416d8`。迁移分支为 `codex/community-module-migration`。

项目实际采用 React / TypeScript / Electron，而非 Unity。继续使用现有 Plugin Host、IndexedDB / Electron 包存储、Unified Content Registry、Activity / Effect / Trigger 引擎及 Worker 沙箱。此次不改存档 ID、D&D 2014 规则版本或房间权威结算模型。

## 兼容边界

纯中立内容经 D&D 适配器进入 Unified Content Registry。旧 V2 包保留一个受校验的 `compatibility/dnd5e-content-v2.json`，其资料预览必须严格等于从兼容数据推导的结果。该文件只包含数据，不执行代码。旧版专属动作、资产及来源信息因此不会在转换时被静默删除。V1 声明包先走已有 V2 规范化流程。

123 个原生法术的数据和显示文本已分离；其余 196 个法术的现有定义、Activity、触发器及召唤选项已预编译为 JSON。法术总表与角色存档中的 ID 不变。

**这不等于所有法术结算都已去除专属逻辑。** 核心法术仍保留可信 `core-spell-transaction` 绑定，旧包仍可能通过兼容适配器结算；手动与部分自动化也保留原覆盖级别。强酸箭延迟伤害、墙体攻击、蛛网燃烧等既有专属行为没有在此次数据迁移中重写。

以下内容显式保留边界，不能宣称已经具备：

- 独立自定义 Condition 条目的 D&D 执行适配；当前法术仍使用既有标准状态和结构化 Effect。
- 任意第三方脚本通过 `.starmod` 请求角色写入、网络或 UI 注入。它们被拒绝，不会降级为无约束执行。
- 授权商业内容的账号权益提供方，以及具备签名、审核和下架流程的官方模块仓库。
- 将旧 V2 包的兼容层彻底删除，或把全部原生法术专属结算改写为通用操作。这是后续引擎迁移，不能用移动数据文件冒充完成。

## 格式与扩展

```
manifest.json
compendium/entries.json
automation/<type>-<id>.json
localization/zh-CN.json
assets/icons/*.png|jpg|jpeg|webp
compatibility/dnd5e-content-v2.json   # 仅旧内容适配包
```

清单的 `files` 覆盖每个非清单文件的 SHA-256。新条目通过 `automationFile` 引用自动化数据；读入后还原为 `automationData` 并进入现有规则校验器。不得添加 JavaScript、HTML 或外部网络资源以绕过数据包权限。

限制：压缩包 32 MiB、单文件 8 MiB、展开总量 48 MiB、文件数 4096、资料条目 2048；D&D Unified 导入仍受自身 512 条目和 8 MiB 校验限制。拒绝路径穿越、重名、符号链接、加密 ZIP、截断目录、缺失/损坏哈希和不支持的文件。哈希保证字节完整性，不代表作者身份签名。

依赖支持完整语义版本的比较、区间、`^`、`~`、`*`、`||`。无法无损表达的旧范围会报错，不会被擅自放宽。中立包最低应用版本为导出时的应用版本。

## 手工验收

1. 刷新 DM 端；在工坊创建一个测试法术或特性，选择“导出 .starmod”。在模块管理中导入，核对名称、版本、来源、许可、权限及数量。
2. 本地模式下停用测试包，确认内容消失；重新启用并刷新，确认内容恢复。让另一包依赖它，确认不能直接停用被依赖包。
3. 选择“编辑本地覆盖”，载入条目，修改名称与说明，保存本地覆盖。刷新后重新打开，草稿应保留，未应用前已启用规则不变。
4. 原包更新后打开旧覆盖，确认显示冲突；核对并保存后才能应用。选择“恢复原包条目”应只删除本地草稿。
5. 应用或导出覆盖包；再次导入，确认校验成功。故意填写无效规则字段，必须报错且不改变现有启用包。
6. 在联网房间以 DM 导入允许房间分发的包，检查玩家取得相同运行包版本与哈希；禁止直接上传未经投影的 ZIP。
7. 回归火球术、强酸箭、石墙术：检查消耗、豁免/命中、延迟伤害及墙段可被攻击。数据对照不替代这些交互验收。

## 开发验证

- `npm run generate:srd-activities`：可重复构建数据，不将作者编译器打包到应用。
- `coreSpellDataMigration.test.ts`：123 个原生法术对照迁移前固定摘要。
- `exportSnapshot.migration.test.ts`：所有法术定义、Activity、完整注册以及召唤边界严格相等。
- `src/domain/packages/*.test.ts`：清单、依赖、ZIP 防护、本地化、覆盖、注册和导入接口。
- `starModAdapter.test.ts`：新旧包往返、旧包预览不可伪造、房间投影、依赖范围不被放宽。

基线问题另行记录：原 PR 的地图回归与架构审计并非全绿；`dnd5eActivityCombatE2e.test.ts` 的效果到期用例在迁移前独立检出中同样失败。不能把这些失败描述为本轮已修复，也不能仅凭定向测试通过就宣称全仓测试通过。

本次执行记录：9 个定向测试文件、114 项测试通过；较广的 Activity 回归为 320 项通过、1 项上述基线失败。完整 TypeScript 类型检查、新增及接入代码的 ESLint 通过，Vite 生产构建、生产包预算和私有内容边界审计通过。实际 DM/玩家双端手工交互按上面的步骤验收，不能由这些单元测试替代。

`starModHost.test.ts` 使用真实 Host 和内存桌面存储适配器，覆盖安装、持久化、依赖乱序重载、禁止破坏依赖的更新、失败恢复、停用与卸载；另验证停用包更新失败后仍保持停用。

前端构建已更新本地 `dist`，浏览器刷新后载入。服务端对原始 ZIP 上传的新增拒绝检查，需要共享服务下次正常重启或部署后生效；正常房间流程发送的是已验证 JSON 运行投影。
