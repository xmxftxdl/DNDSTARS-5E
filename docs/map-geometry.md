# 地图几何与动态可见性 V1

`map-geometry` 是独立于地图图片、Token 和静态战争迷雾的 DM 权威共享资源。它负责可重复计算的墙、门、障碍物、效果线和动态视野。

## 数据模型

- 墙：折线端点、稳定 `edgeIds`、阻挡视线、阻挡移动、阻挡效果线、底部高度和实体高度。
- 门：通过 `wallEdgeId + startT/endT` 参数化绑定到稳定墙边；开关、锁具和物理完整度分别记录，暗门继续按成员揭示。打开或已摧毁的门不参与碰撞或射线判定。
- 障碍物：多边形占地、三类阻挡、高度，以及无／半身／四分之三／全身掩护。
- Token：可设置海拔、视野距离，以及按视线／始终可见／仅 DM 可见。
- 视野：可按地图启用，设置默认视野距离，并选择共享全队视野或只使用当前控制角色。
- 光照：地图可设为明亮、微光或黑暗；Token 可携带光源，DM 也可放置独立场景光源；两类光源都具有明亮／微光半径、颜色与高度，并按墙和门生成阴影。角色可单独设置黑暗视觉距离。

所有实体由 DM 端写入；共享服务使用房间成员身份和 CAS revision 保护资源。玩家不能写 `maps` 或 `map-geometry`。

## DM 编辑与恢复

编辑器支持 50 步撤销／重做、复制选中实体、按当前地图网格吸附，以及单张地图几何 JSON 的导入导出。也可导入 `.uvtt`／`.dd2vtt`／`.df2vtt` 的墙、门与光源；文件带有内嵌背景图时，可直接创建匹配源分辨率和网格尺寸的新地图。图片墙体识别只生成候选线，必须由 DM 明确确认后才追加到权威几何。历史栈只存在于当前 DM 客户端，权威几何快照仍由房间共享资源保存；导入文件必须先通过同一套运行时 schema 与关系完整性校验才会覆盖当前地图。

### 几何诊断与图片识别

- DM 可打开房间诊断层，查看派生房间着色、密闭状态、稳定墙边 ID、门 Portal 的房间连接，以及结构关系问题计数。诊断格数量有上限，超限时界面会明确提示。
- 图片识别只用于没有矢量几何的 PNG／JPEG／WebP；UVTT／DD2VTT 始终直接使用文件自带的墙、门和光源数据。识别器在 Web Worker 中执行极性无关的自适应边缘分析、任意角度长线提取和局部曲线近似，并过滤覆盖整图、等间距重复的常见网格线。
- 边缘倍率、最短线比例和“仅主体”中心带可调；显式 ROI 也由识别 API 支持。解码后的分析图按文件缓存，重算时只重新执行几何内核。候选设有 1,200 条安全上限，达到上限时 UI 会提示提高阈值或缩小范围。
- 识别结果先以青色虚线叠加在地图上；DM 可点击单条候选线删除，再选择接受或放弃。切换地图会清除尚未接受的候选，避免写入错误地图。
- 回归夹具覆盖裁切 UVTT、V3 参数化门和门状态；性能测试覆盖 1,000／5,000／10,000 墙段的编译、空间索引和批量射线预算。

## Schema V3 与共享几何内核

- 浏览器与共享服务端共同使用 `shared/map-geometry-kernel.mjs` 编译墙洞、有效阻挡线和射线命中，避免两端算法漂移。
- 编译结果按几何签名缓存，并建立空间分块索引；移动、视野、光照与效果线复用同一批有效线段。
- V1/V2 数据载入时自动补齐稳定墙边、参数化开口和拆分门状态；继续输出旧 `state` 作为兼容字段。
- 服务端持久化边界会检查墙边 ID 唯一性、父边存在性、参数范围和开口重叠。损坏的 Schema V3 几何会 fail closed。
- “房间”是从阻挡线和门 Portal 派生的缓存图，不是额外的权威布尔状态；开门后会重新派生连通区域。

## Headless 接入

### 海拔口径

- 格子高度工具通过单击或拖动选择地图格，系统自动合并相邻格并记录地形表面的绝对海拔；不再要求手绘封闭多边形。
- 高度区域只显示合并选区的外边界，内部保持透明且不显示格间共享边；高度轮廓不提供自由控制点，以免破坏网格对齐。
- Token 与光源的编辑器使用“离地高度”，运行时统一换算为“地形海拔＋离地高度”的绝对海拔。
- 旧地图中未记录海拔、或海拔低于当前地表的 Token，会在权威结算、视线、照明与寻路时自动贴合地表。
- 地面移动的路径节点按地形海拔逐格计算，单步高差超过 10 尺会被拒绝；飞行路径使用绝对海拔进行三维插值。

- 玩家移动、怪物手动移动、怪物寻路，以及雷鸣波／斥力魔爆／散打宗推离等强制移动都会检查移动阻挡。
- 地图桥在创建 Headless 战斗快照时计算有方向的掩护和效果线。
- 半身掩护为攻击目标提供 `+2 AC`，四分之三掩护提供 `+5 AC`，全身掩护禁止命中；天然 20 也不能穿过全身掩护。
- 攻击者与目标之间的其他玩家、怪物或 NPC Token 也会参与四射线采样；射线穿过其占地与高度时提供半身掩护。
- 普通武器攻击在提交骰子事务前显示自动掩护、来源、无掩护 AC 与实际目标 AC。玩家确认后，DM Host 会在掷骰前收到同一事务的裁定窗；DM 可以仅对这一笔攻击覆盖为无／半身／四分之三／全身掩护。裁定期间事务保持锁定，30 秒无操作会采用自动判定继续。覆盖不写回地图几何，玩家请求伪造覆盖字段会被权威层拒绝。
- 敏捷豁免会获得半身 `+2` 或四分之三 `+5`。点起源范围法术使用实际范围落点计算效果线；自起源法术使用施法者位置。
- 高度判定沿射线插值，不只比较两个 Token 的最高海拔。移动碰撞按移动 Token 的占地和海拔处理。
- 玩家和怪物的权威寻路结果会把最多 128 个路径点随最终 Token 快照同步。各端以本地时钟按路径分段插值并显示短暂路线，不逐格写入共享状态；伤害区域提前截停时，路线也在权威最终位置截断。
- 怪物自动寻路每回合最多穿过一扇关闭但未上锁的门，并由 Headless 消耗一次物件交互。路径需要第二扇门或该资源已用尽时会 fail closed，不允许 AI 绕过行动经济。

### 门交互事务

- 玩家点击自己可见的门，只能请求开门、关门、使用钥匙、盗贼工具开锁或力量破门；不能直接改写几何。
- DM Host 按最新 Token 位置、门状态、角色物品栏、工具、技能与行动经济重建请求。开锁、破门和搜索可配置独立 DC。
- 每次玩家交互先进入 `dm-adjudication` Interrupt。DM 可拒绝、调整 DC，或直接指定成功／失败；批准前事务保持锁定，不消费动作也不修改门。
- 检定骰由 Host 骰子层生成。战斗中的开锁、破门和搜索会消费动作；开门、关门和使用钥匙优先消费每回合一次的免费物件交互，第二次改为消费主动动作。两类资源均由 Headless 事务验证；探索阶段不依赖先攻顺序。
- 暗门发现按 `roomMemberId` 写入揭示名单。服务端只向已发现成员投影真实门，其余成员仍收到匿名墙。
- 玩家主动搜索只提交地图坐标与感知／调查方式，不提交暗门 ID、名称或 DC。DM Host 使用完整权威几何在附近解析候选暗门；失败和空区域返回相同的“没有发现异常”，共享中断也不会携带隐藏门 ID 或隐藏 DC。

## 玩家可见性安全

动态视野不在玩家端覆盖黑色遮罩——整图黑幕只由战争迷雾层（全图填充或 DM 画的 cover 形状）决定，与 Owlbear 语义一致。动态视野负责的是保密和视线形状：

1. 玩家请求 `maps` 时必须携带当前房间成员 ID。
2. 服务端根据玩家当前控制角色、共享视野设置、距离、墙体和门状态计算可见 Token。
3. 躲藏 Token 还必须通过观察者角色的被动察觉；未被察觉时会在 JSON 序列化前完整删除。共享队伍视野启用时，任一具有视线的队员察觉成功即可共享位置。
4. 隐形但没有成功躲藏的生物仍可被定位，但服务端只下发匿名“未见生物”位置标记；名称、怪物模板、生命值、体型和状态不会进入玩家响应。
5. `dm-only` 和不可见的非玩家 Token 在 JSON 序列化前删除；依附于隐藏 Token 的插件区域也一并删除。
6. 玩家读取 `map-geometry` 时，关闭或上锁的暗门会被投影成匿名墙；响应中不包含暗门 ID、名称或门状态。
7. 几何改变会触发玩家端立即重新拉取地图投影，使关门、开门或新增墙体后的 Token 可见性及时更新。
8. 几何或角色察觉资源损坏时服务端 fail closed，只保留玩家 Token 和明确标记为始终可见的 Token。

客户端的可见多边形用来在战争迷雾上打洞（迷雾覆盖处玩家靠实际视野看穿）；服务端投影负责保密，两者职责不同。没有画迷雾的地图即使开着动态视野，底图对玩家也完全可见，只有 Token 仍按视线过滤。

## 光照与探索记忆

- 服务端 Token 投影会同时检查距离、墙体、环境光、可用光源和查看者的黑暗视觉。黑暗中的目标如果既未被照亮、又超出黑暗视觉，不会进入玩家响应。
- 客户端把环境黑暗、Token 光源、当前可见多边形和已探索区域分层渲染；DM 正常地图视图也会显示环境亮度与场景光源，但使用较低遮罩强度以保留管理可读性。环境亮度负责地图观感，动态视野开关仍独立决定黑暗中的 Token 权威可见性。全图填充迷雾下，已探索但当前不可见的区域会掀开迷雾但不会恢复隐藏 Token。
- DM 在“几何 → 光源”中点击地图即可设定一个默认 20 尺明亮＋20 尺微光的中心，也可从中心向外拖动直接设定半径；选择已有光源后可拖动中心点，并编辑预设、半径、高度与颜色。光照多边形会受到墙、关闭的门和高度区间裁切。
- `map-exploration` 是独立的 DM 权威共享资源。DM 根据每个玩家 Token 的可见多边形持续追加探索记录；共享队伍视野打开时，成员共享当前探索结果。
- 玩家读取探索资源时，服务端只保留请求者 `roomMemberId` 下的数据。其他成员走过的私有区域不会出现在响应中。

## V1 边界

- 墙编辑器当前每次拖动创建一个线段；复杂墙体由多个线段组成。
- 障碍物编辑器当前创建矩形多边形，底层模型已经支持任意多边形。
- 门锁仍只能由 DM 权威事务改写；玩家开锁、使用钥匙、破门和区域搜索均已接入 Headless 行动经济与 `dm-adjudication` Interrupt。
- 场景光源和 Token 光源已统一参与服务端可见性与客户端带阴影光照；魔法黑暗覆盖、彩色混光和可开关灯具的玩家交互仍属于后续增强。
- 隐形的攻防优劣势、攻击后暴露，以及带 `casts-spell` 解除条件的施法后暴露均由 Headless 处理；盲视、震颤感知和真实视觉已按范围接入地图视线、隐藏 Token 服务端安全投影与 Headless 可见性。幻象、以太位面、变形者原形及主动搜索移动目标仍属于后续感知增强。
