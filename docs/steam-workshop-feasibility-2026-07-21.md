## 三、有利资产（可直接映射到 Steam 生态）

### 1. 创意工坊技术内核已存在

现有房间规则包几乎就是 Workshop item 的工程原型：

| Workshop 常见能力 | 仓库现状 |
|-------------------|----------|
| 单文件模组包 | `.dndstars5e`（自包含，禁 `import`） |
| 完整性校验 | SHA-256 `integrity`，激活前再校验 |
| 版本与迁移 | `version` + `stateSchemaVersion` + 连续 `migrations` |
| 沙箱 | Worker：禁联网、禁写盘、禁 eval；只出白名单 capability |
| 创作者工具 | DM「规则包工作室」无码表单 → 下载/发布 |
| 清单元数据 | `id` / `publisher` / `license` |

映射设想：Steam Workshop item = 现有插件字节 + 封面/描述；订阅后写入本机 IndexedDB 或 Steam userdata；进房时仍用「房间钉扎版本」防不同步——**房间清单机制应保留**，不要改成「每人订阅什么就各玩各的」。

### 2. 联机权威模型成熟

- DM Host + Headless + ACK + Interrupt  
- 协议版本握手（当前客户端/服务端 **v5**）  
- 资源 CAS（`X-Stars-Expected-Revision`）  
- 观众席、房间码、锁房、密码、踢人  
- 账号抽象可换提供者（文档已写可替换云端登录）→ 未来可绑 **SteamID**

适合「好友开房 / 密码房」模型，不必一上来做 MMO 大厅。

### 3. 内容策略与 Workshop 兼容

- 核心包：**仅 SRD 5.1**（CC BY 4.0），第三方走插件命名空间  
- 平台不索引、不背书第三方——上架时可声明「创意工坊内容由创作者负责」  
- 怪物/魔法物品生成钉死上游 commit，可审计

## 四、硬障碍（上架前必须处理）

### 1. 版权：法术中文正文（最高优先级）

`ATTRIBUTION.md` 已写明：法术书 319 条中文正文来自维护者提供的 **《玩家手册》中译 PDF**，**不是** WotC 官方 SRD 中文。

- Steam 商业分发前：**必须**换成自译 / 正式授权译本 / 或仅英文明文 + 社区 Workshop 汉化包  
- 在此之前任何「Steam 页」都会踩版权雷  
- 机翻魔法物品正文（Lingva）另有质量问题，但许可路径相对更接近 CC-BY 衍生；仍建议抽检 + 禁译词回归

### 2. 无桌面壳 / 无 Steamworks

当前是 **浏览器 + 本机 Node（5273）**：

- `package.json` 无 Electron / Tauri / Steam  
- 玩家要自己跑服务或依赖 DM 本机——不符合 Steam「双击即玩」预期  

最低可行产品形态建议：

1. **Tauri 或 Electron 壳**内嵌 UI  
2. 壳内**静默拉起**本地 shared-server（或连官方/自建中继）  
3. 可选：Steam 好友邀请深链 → 填入房间码 / lobby id  

### 3. 联机拓扑未产品化

- 默认 HTTP、CORS `*`、无正式 Docker/HTTPS/NAT 文档  
- 好友异地联机依赖穿透或托管；Workshop 模组同步也需要「权威房间」可达  

Steam 常见解法（择一或组合）：

- **DM 主机 + Steam Networking / 中继**（延迟与权威仍在 DM）  
- **轻量专用服务器**（把现有 `shared-server-core` 容器化，按房间计费或免费额度）  

### 4. 无 UGC / EULA / 内容政策

仓库无 LICENSE（面向终端用户）、无 EULA、无创意工坊内容指引。Steam Workshop **强制要求**可接受的 UGC 条款与下架流程。  
插件清单里的 `license` 字段不够替代平台级协议。

### 5. 插件资产能力偏窄

当前插件：**无自定义图片/音频包**；图标为平台枚举；区域视觉为平台预设名。  
创意工坊用户期待「地图包、立绘包、音效包」。需要扩展 **签名资源包**（与规则包分轨或同包），并继续 fail-closed 校验大小与类型——否则审核与恶意内容难控。

### 6. 商标与命名

「D&D / 龙与地下城」等在 Steam 商店页、胶囊图、标签上的使用须单独对照 WotC / Hasbro 商业政策与 SRD 要求；工程层未处理。建议产品名与「SRD 兼容」表述拆分（许多 VTT 用自有品牌 + “compatible with SRD 5.1”）。

### 7. 应用内署名缺失

CC BY 要求合理署名。`ATTRIBUTION.md` 在仓库里，**应用 UI 未见稳定 About/页脚署名**。上架构建必须内嵌可见署名。

## 五、创意工坊可行性（专项）

### 结论：**值得做，且应「后置」于 Steam 本体**

| 阶段 | 做什么 | 依赖 |
|------|--------|------|
| **W0 现状** | 房间内插件分发 | 已有 |
| **W1 Steam 本体** | 壳 + 合规文本 + 联机 | 无 Workshop 也能卖 |
| **W2 本机模组库** | 订阅/导入的包进「已安装模组」，房间激活仍钉扎 | 小改客户端 |
| **W3 公开 Workshop** | Steamworks ISteamUGC：上传、订阅、更新、可见性 | W1 + EULA + 审核策略 |
| **W4 资源型模组** | 地图/立绘/音频包 | 新资源管道 + 配额 |

### 与现有插件 API 的对齐建议

保持 **「声明式白名单 + Host 结算」**，禁止 Workshop 上传任意可执行网页脚本到主文档：

- 允许：现有 `registerItem` / `registerSpell` / 特性 / 区域声明 / migrations  
- 禁止：绕过 Worker 的主线程代码、远程加载、未签名二进制  
- 上传前：服务端或 Steam 侧再跑一遍与本机相同的 schema 校验（你们已有 fail-closed 传统）

### 风险控制（Workshop 特有）

1. **恶意模组**：沙箱已较强；仍需限制包体大小、禁止外链执行、举报下架  
2. **版权侵权模组**（整本 PHB PDF 进包）：平台免责声明 + DMCA 流程；核心永不内置非 SRD  
3. **版本分裂**：房间必须继续 **钉扎 plugin hash**；订阅最新版 ≠ 自动进当前战役  
4. **付费模组**：Steam 分成与你们「房间托管」是否收费要产品决策；技术上可先只做免费 UGC  

### 不建议一上来做的

- 用 Workshop 分发「完整规则引擎补丁」（改 Host 内核）——只分发数据/声明  
- 允许模组直连外网（破坏沙箱与隐私）  
- 在核心包未清 PHB 中文之前开放「汉化模组官方推荐」——易被视作规避
