# DNDSTARS-5E 全域审查报告

审查日期：2026-09-09。基线：`f9bba8cf` 加当前未提交工作区，不能把结论只归到该提交。审查期间没有修改业务代码、用户角色、战役或运行端口；新增内容为本目录下的报告、检查输出和复现用例。

## 结论

当前版本不宜直接作为稳定发布版本。最需要先处理的是**图片配额可能删除仍在使用的素材**，以及**标准构建被架构门禁阻断**。投掷提示还有两个已复现的业务缺陷：网络失败后重试会被去重逻辑吞掉；不同投掷只要角色名称相同，最终提示就可能被误判为重复。

本报告列出 10 项问题：2 项高优先级、6 项中优先级、2 项低优先级。它们包括业务缺陷、数据风险和工程质量门禁问题，并不等于发现了 10 个当前用户已经遇到的故障。另列尚未完成验证的风险，不混入已确认问题数量。

## 高优先级

### H1：图片配额会直接淘汰仍可能被引用的文件

**证据：**`scripts/shared-server-core.mjs:266` 将 `IMAGE_COUNT_LIMIT` 设为 128；`:2654` 的 `enforceImageQuota` 只按文件修改时间排序，直接删除最旧文件和元数据。`:14955` 在上传后调用它，没有传入或查询地图、讲义等引用关系，也不将删除列表告知上传者。

**触发：**同一素材目录已有 128 个文件，最旧素材仍在使用，再上传第 129 个文件。最旧文件照样成为删除对象。现有 `src/lib/sharedServerCore.test.ts:4993` 已验证“超过配额删除最旧文件”的实现行为，并在本次全量测试中通过。

**影响：**旧地图背景、讲义图片等可能随后加载失败。自动快照可能提供恢复机会，但不构成活跃引用保护，也不能据此保证无数据损失。这里是已确认的淘汰行为与引用保护缺失，没有对用户现有素材执行破坏性复现。

**建议：**配额不足时拒绝新上传并说明原因，或只清理确认无引用的资源；增加回收站、显式删除记录和恢复路径。验收须覆盖“最旧文件仍被地图/讲义引用”和“多个上传并发触发配额”。

### H2：标准构建入口当前无法通过

**证据：**`package.json:32` 的 `build` 首先执行架构审计。本次实际失败为：

| 文件 | 当前行数 | 上限 |
| --- | ---: | ---: |
| MapsWorkspacePage.tsx | 41,375 | 41,294 |
| MapCanvas.tsx | 3,425 | 3,418 |
| MapTokenNode.tsx | 1,765 | 1,761 |

**影响：**标准构建和依赖它的桌面打包无法继续。直接执行 Vite 可以绕过门禁，但不能据此宣称标准发布检查通过。

**建议：**优先提取投掷确认/恢复等完整职责，降低地图页面耦合，再执行完整 `npm run build:check`。不要只增加行数上限来掩盖持续增长。

## 中优先级

### M1：网络发送失败后，横幅和动画重试被误吞

**证据：**`src/lib/combatPresentation.ts:350` 在调用网络传输前执行发布去重；`src/lib/combatBannerReplay.ts:28` 随即把 ID 保存为已处理。网络失败没有撤销标记。传输层 `src/lib/sharedApi.ts:822` 在所有候选地址失败后会抛错。

**复现：**第一次发布火焰箭横幅，模拟传输离线；恢复后用相同事件 ID 重试。第二次调用返回，但网络方法总共只调用一次。见 `probes.test.ts` 的 AUDIT-01。

**影响：**本地可能已经展示，远端从未收到；刷新恢复也不能补发该 ID。只修复重复播放，反而引入了漏播路径。

**建议：**把本地展示去重与可靠发送分开。发送采用 pending/sent 状态，收到服务端成功响应后再确认 sent；失败允许重试。服务端按稳定事件 ID 幂等。验收覆盖离线、超时但服务端已收到、重连及刷新。

### M2：不同投掷可能互相吞掉命中/豁免最终提示

**证据：**`src/presentation/maps/diceCheckCueLedger.ts:24` 用“类型、actorName、targetName”匹配预览与最终结果，不用投掷 ID、角色 ID、地图或房间。`diceCheckOutcome.ts` 生成最终结果时也没有携带关联的 rollId。

**复现：**记录 roll-A 的命中预览，再提交独立 roll-B 的命中最终结果；名称相同，即使 rollId 不同也返回不展示。见 AUDIT-02。

**触发条件：**前一次预览没有正常匹配最终事件，例如取消、中断、恢复漏事件；或同名角色/跨地图事件交错。正常连续完整流程不一定触发。

**建议：**端到端携带房间、地图、事务、投掷与角色 ID，按同一投掷匹配；取消事务时清理未完成预览，设置合理过期时间。不能依赖显示名称作主键。

### M3：回归测试门禁已失效，关键骰面验证没有实际执行到断言

**证据：**全量测试 25 项失败。其中 `src/lib/dicePhysicalReroll.test.ts:44`、`:55` 调用 `createDiceBox`，但新代码在 `src/lib/diceEngine.ts:511` 使用 document，默认 Node 测试环境没有 document，两项均在核心断言前抛错。

其他失败包括源码样式/字符串定位，以及事件对象增加字段后的严格相等比较。`src/pages/maps/diceOwnership.test.ts:29` 要求调用数量大于 300，但当前扫描到 271，导致它还没执行下一条缺失归属断言就已失败。**271 不能证明缺少归属，也不能证明归属全正确。**

本次另以 CONTROL-01 绕过过时的数量门槛，确认这 271 处调用不存在原检测器定义的“缺少归属参数”：均有参数，字面对象含归属/自由投掷标记或展开项。这只是语法级控制；传入变量、展开项的实际值以及角色是否选对，仍须追踪运行路径。

**影响：**当前测试无法可靠拦住“显示 15，朝上却是 12”和重投骰面问题。另一方面，大量预期漂移会让真正回归混在噪声里。

**建议：**分离物理数值逻辑和 DOM 光效；为渲染集成补合适环境，保留真实浏览器数值/朝向验证。将纯源码字符串断言改成可观察行为；事件字段扩展后仍须严格校验关键规则字段，不可批量改为无约束匹配。完整失败列表保留在 `failed-tests.json`，其中法术相关失败尚未全部逐条判定为业务回归或预期过时。

### M4：可选 AI 配置损坏会阻止整个服务启动

**证据：**`scripts/static-server.mjs:141`、`scripts/vite-server.mjs:116` 在创建核心服务前直接 await AI 服务加载。`scripts/player-ai-service.mjs:234` 直接传播配置错误；`scripts/local-ai-config-store.mjs:174` 只把 ENOENT 当作未配置，JSON 损坏、版本不匹配、解密失败都会重新抛出。

**触发：**存在配置但格式损坏，或复制到无法解密该秘密的 Windows 用户环境。这里是完整代码路径确认，未改写用户配置进行复现。

**影响：**不需要 AI 的地图和骰盘也无法启动。配置不存在时正常降级，问题只在“存在但不可用”的分支。

**建议：**只禁用相关 AI 功能并给管理端可读错误，核心桌游服务继续启动。不得以明文输出密钥或忽略所有生产安全配置错误作为修复。

### M5：默认 lint 在当前仓库规模下堆耗尽

**证据：**实际 `npm run lint` 在约 4 GB V8 堆上限处崩溃，记录为 `Allocation failed - JavaScript heap out of memory`。配置 `eslint.config.js` 的全局排除仅显式包含 dist；地图主文件已超过四万行。8 GB 堆重试的日志进一步证实，它正在扫描 `.codex-temp/monster-verification-20260904/snapshot/src/pages/MapsWorkspacePage.tsx` 旧快照。驻留内存约 8.5 GB 时停止了该复核，避免继续占用本地服务资源。

**影响：**默认质量检查会把临时备份源码纳入检查，增加大量无效工作，并可能报告旧代码的问题。默认命令本次无法完成；这不是“lint 没有报错”。旧快照被扫描已确认，堆耗尽的具体内存分配热点尚未分析。

**建议：**明确生产源码/测试的 lint 范围、排除生成物和临时产物，并拆分批次；诊断内存后配置合理堆限制。优先拆分大文件，避免将不断抬高内存作为唯一方案。

### M6：开发依赖链存在已知漏洞，需要更新锁文件

**证据：**`npm-audit-all.json` 报告 4 个受影响包：browserslist（high）、baseline-browser-mapping、vitest、@vitest/mocker（后三项 moderate），均给出可修复。Vitest 与 mocker 涉及同一公告，不能简单算作四个独立漏洞。

Vitest/mocker 的路径读取问题修复于 4.1.11；实际测试运行版本为 4.1.10。未经认证的利用需要暴露使用对应插件的开发服务；仓库检索未发现直接使用 mockerPlugin/interceptorPlugin，因此本报告不宣称当前 localhost 应用存在可直接利用的任意文件读取。[Vitest 公告](https://github.com/advisories/GHSA-82fw-gwwq-j7x9)

Browserslist 公告涉及无界缓存的内存增长，另有自定义 stats 输入问题；baseline-browser-mapping 公告涉及无效输入导致进程结束。它们是工具链风险，**没有证据说明本次 ESLint OOM 就由该漏洞导致**。[Browserslist 公告](https://github.com/advisories/GHSA-c83g-rgw3-j3cx)、[baseline-browser-mapping 公告](https://github.com/advisories/GHSA-w5vr-8v7q-w6rv)

**建议：**在独立修复中更新相关直接/传递依赖及锁文件，再跑测试与构建。不要盲目执行带 force 的升级。本次只审计，没有改变依赖安装内容。

## 低优先级


### L1：损坏的投掷检查点会让恢复流程直接抛异常

**证据：**`src/presentation/maps/dicePoolCheckpoint.ts:8` 在 try/catch 外读取 `value.values.length`，没有先验证 values 是数组。存储中同 ID 记录仅含 `{sides:20}` 就抛 TypeError，AUDIT-03 已复现。

**影响：**异常、旧格式或损坏的会话存储可能中断待确认投掷恢复。不是说正常 sessionStorage 会自行产生该记录。

**建议：**完整校验记录类型、数组和值域；无效项单独丢弃并走权威恢复，不能让一条坏记录阻止整个页面。

### L2：检查点淘汰按首次插入顺序，刚更新的旧事务也可能被删除

**证据：**同文件 `writeDicePoolCheckpoint` 更新已有 Map/对象键后不刷新插入顺序，却用头部/末尾 500 项截断。AUDIT-04 建立 500 条记录，刚将最早记录更新为 confirmed，再写新记录，该 confirmed 记录就从持久化内容中消失。

**影响：**长会话跨越容量上限且仍需要旧事务检查点时，刷新恢复可能失去已确认结果。完整动作是否因此重掷取决于外围事务是否还需重放，本次没有把这一步推论列为已复现。

**建议：**按最近使用时间维护顺序，优先保留未完成事务需要的记录；确认结果在服务端按事务保存，浏览器检查点仅作缓存。

## 本次未发现问题的已检查控制

服务端在统一入口禁止玩家删除及上传共享图片，禁止观战者执行非 GET 操作；不能只看图片路由中“已认证即放行”就误报越权。相关入口位于 `scripts/shared-server-core.mjs:13391`。角色声明还会由认证成员身份覆盖，玩家骰子记录强制 public。讲义图片 GET 存在按成员投影的可见性检查。

桌面窗口启用 contextIsolation、关闭 nodeIntegration、启用 sandbox，并限制外部窗口；归档路径逃逸与包完整性测试本次通过。PDF 渲染具备排队取消、renderTask.cancel、TextLayer.cancel 和 loadingTask.destroy。上述均只是具体控制有效的证据，不代表整个安全和性能领域无风险。

## 建议修复顺序与验收

1. 保护正在引用的图片，恢复标准 build 门禁；先避免资产损失和无法发布。
2. 将投掷、事务、提示的关联 ID 贯穿双端，分开网络投递状态和展示去重；同时修正 AI 可选服务故障隔离。
3. 更新有公告的开发依赖，恢复全量测试和 lint，先让骰面校验真正运行；逐项确认 25 个失败的原因，不批量降低断言强度。
4. 补服务端投掷恢复和容量测试，再完成真实浏览器及移动端回归矩阵。

关键验收标准：同一事务只生成一次权威数值、只消耗一次资源；玩家与 DM 的朝上面及显示数值一致；新动作必有提示、已播放动作刷新不重播；断网重试不漏事件；施法者负责命中和伤害、豁免者负责豁免；自由投掷不等待 DM 二次确认；受引用素材不因上传其他文件而失效。
