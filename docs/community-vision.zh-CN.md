# 中文 VTT 平台与社区规划

整理日期：2026-09-21。

后续已制作社区交互演示，见 [community-demo.md](./community-demo.md)。按最新用户要求，论坛以 DND、COC、三角机构、匕首之心划分规则板块；每日签到奖励 2 钱币，支持消耗钱币。演示采用每次支持 1 钱币、钱币不直接兑换 AI 点数的方案；下文早期额度仅保留为规划参考，不是当前演示的实际发奖规则。

用户明确目标：打造中文 VTT 集大成者，包含论坛／贴吧式社区、插件与资源分享，并奖励资源上传者和活跃用户。此前讨论过以 AI 点数作为奖励。下面的功能顺序、额度和技术划分属于建议，尚未实施或最终定案。

## 产品定位

围绕中文玩家的完整跑团过程：找团 → 备团 → 开团 → 战报与分享 → 复用他人作品。提供统一账号、内容搜索、个人资料与通知，让社区资源可以直接进入游戏房间。

先把 D&D 5e 的体验做稳定，再通过规则适配层扩展其他系统。规则版本、自定义房规与资源适用版本必须明确标注。确定性的规则由规则引擎处理，AI 提供创作与检索辅助，DM 保留裁定和覆盖权限。

## 主要模块

| 模块 | 主要职责 |
| --- | --- |
| 跑团桌面 | 地图、角色卡、骰子、语音、先攻、规则自动化、日志、撤回、断线恢复、存档与导出 |
| 社区论坛 | 求助与反馈、规则讨论、战报、原创教程、作品展示；后续开放有管理人的主题吧 |
| 创作中心 | 地图、Token、音效、怪物、物品、法术、遭遇、完整冒险包与可执行插件 |
| 找团大厅 | 招募、规则与版本、时间及时区、语音／文字、风格、新手友好、报名与排期 |
| 创作工具 | 将本地内容整理为可分享包，自动检查缺失素材、依赖、兼容性和私密内容 |
| AI 助手 | NPC 与遭遇草稿、背景素材、战报整理、内容检索；使用前展示预计点数消耗 |
| 创作者主页 | 作品、更新记录、关注、贡献记录、徽章与反馈 |

社区首页展示正在招募的团、精选资源、新手入口和近期讨论。新手应能从示例冒险快速开团。

## 论坛与创作中心如何结合

论坛承担讨论，作品页承担版本、依赖、安装与维护。一个资源关联一个主要讨论帖，跨版推荐使用引用而非重新上传文件。统一搜索可按规则、等级、人数、时长、语言、版本和资源类型筛选。

初期只建少数官方版块；有实际讨论量与愿意维护的人后，再开放用户创建主题吧。主题吧支持置顶、精华、标签、吧主管理和举报。私有战役与公开社区分开，战报和资源发布前显示预览、可见范围及剧透选项。

每个资源记录作者、上传者、来源、授权、依赖与适用版本。原创、授权转载、翻译、整理和 AI 辅助制作应能分别标注。上传者不自动视为原作者；奖励依据实际贡献发放。公开发布资格与本地私用导入分别处理。

资源操作：预览 → 加入个人库 → 导入房间。当前战役锁定已使用版本，新版本先提示，由 DM 决定是否升级；保留回退与导出能力。

可执行插件与普通素材采用不同审核要求。插件展示权限，按沙箱能力限制访问，记录审核版本；支持依赖检查、禁用和回退。发布采用草稿 → 提交审核 → 发布 → 更新的流程。

## 奖励设计

分开维护三类数据：

- 贡献值：长期积累，用于信誉与荣誉；消费 AI 不扣贡献值。
- AI 点数：用于平台提供的 AI 服务；赠送与购买分别记账。
- 社区等级／徽章：反映参与、帮助和作品维护，不因充值直接获得管理权限。

活跃用户应获得奖励，但活跃不限于在线时长或发帖数量。鼓励真实参与、回答问题、带新人、发布战报、测试资源和维护作品。

以下仅为试运营额度示例，须根据每点对应的 AI 成本和每月预算调整：

| 贡献 | AI 点数示例 | 条件 |
| --- | ---: | --- |
| 首次有效发帖 | 20 | 一次性，通过基础审核 |
| 周活跃任务 | 5–15 | 有效参与且每周限领；不要求每天签到 |
| 原创战报或教程 | 10–30 | 内容合格，每周有限奖励篇数 |
| 回答被采纳 | 10 | 排除自问自答、固定账号相互刷采纳 |
| 首次发布合格原创资源 | 50–200 | 文件可用、来源清晰、审核通过 |
| 有效授权整理或翻译 | 按贡献评定 | 标明原作者与授权，避免重复搬运 |
| 可复现的新 Bug | 20–50 | 官方确认；同一问题不重复奖励 |
| 维护更新、精选作品 | 额外奖励 | 按实质改进与持续使用情况评定 |

上传奖励分为发布基础奖励与后续贡献奖励。后者参考不同真实用户的安装、实际导入使用、有效评价和维护质量，不直接按下载次数兑换点数。新作者保留固定支持额度，不能只让热门作品获得奖励。

点赞、浏览和普通聊天主要增加参与记录，不逐条兑换 AI 点数。平台设置每人、每资源和每月总奖励上限。获奖记录显示原因、关联内容、待审核／已到账状态；支持申诉与违规撤销。

所有点数由服务端账本发放，奖励事件有唯一编号，防止重复到账。活动预算按实际 AI 服务成本核算。奖励点数默认不转让、不兑现；如设置有效期，领取前必须清楚展示。用户自带 API Key 的消费与平台点数分开。

AI 可辅助检查重复内容、整理审核摘要；不单凭模型判断决定作者资格或认定内容违规。初期高额奖励由人工审核，并提供理由。

## 技术组织与建设顺序

采用统一身份与内容编号，明确跑团、社区、资源和点数账本的模块边界。团队较小时可先用模块化单体服务，不必一开始拆大量微服务。论坛短期可评估成熟系统加统一登录，创作中心与房间导入保留平台专用实现。

第一阶段：稳定跑团体验，做好存档、恢复、撤回、权限与规则版本；提供官方示例内容。

第二阶段：上线统一账号下的论坛、创作中心基础上传、审核、搜索、个人库、房间导入、举报，以及人工审核的点数奖励账本。先满足少量真实团持续使用。

第三阶段：上线找团排期、主题吧、创作者主页、版本订阅、插件安装更新及更完善的贡献奖励。

第四阶段：在内容供给和付费需求获得验证后，再评估创作者付费作品、分成、会员和更多规则系统。AI 服务与存储可以承担部分商业化，基础互动不按发帖收费。

不按功能数量判断成功。优先观察新手完成首次开团的比例、真实团的持续使用、资源导入后实际使用、求助解决率、活跃创作者留存，以及每名留存用户对应的 AI 奖励成本。使用统计尽量聚合，不采集私密战役正文用于奖励判断。
