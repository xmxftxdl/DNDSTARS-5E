# 产品级审查：作为跑团专用 APP 的缺口与功能建议 — 2026-07-20

前三轮审查聚焦"已实现的规则是否正确"；这一轮换角度：**一个真实团（1 DM + 3~5 玩家、每周一次、连跑数月）用它跑团，会在哪里卡住**。结论先行：战斗结算的深度在同类工具里已经非常强（DM 权威、Headless、插件沙箱、断线恢复都超过多数开源 VTT），但"战斗之外的跑团"和"内容覆盖广度"是当前短板——一场典型团务大约 40% 时间在战斗内，60% 在探索、社交、查规则和 DM 叙事，后者目前几乎没有工具支撑。

---

## 一、内容覆盖缺口（最影响"能不能跑起来"）

### 1. 怪物目录只有 10 只，是全局最大瓶颈 ⭐
`src/rulesets/dnd5e/monsters.ts` 目前约 10 个怪物；SRD 5.1 有 300+ 只。这意味着 DM 跑任何一个现成模组都无法从工具里找到怪。且缺三个配套能力：

- **结构化效果缺口**：传奇动作、巢穴动作、施法怪物（比如法师型 NPC）、群集（swarm）、变形、再生、飞行/游泳战斗——路线图已列但未开工。CR 3 以上的怪几乎都带其中至少一项。
- **没有自定义怪物编辑器**：插件召唤只能引用 SRD 静态表，DM 无法录入自己的 homebrew 怪或模组怪。建议做一个"怪物工坊"（表单 → 结构化 stat block → 走 monsterSchema 校验 → 存入房间资源），这比补完 SRD 目录见效更快，因为它同时解决 SRD 之外的需求。
- **建议路径**：SRD 怪物数据是机器可读的（开源 JSON 数据集很多，CC-BY 兼容），可以写一个提取脚本批量转换 + `monsterSchema` 校验 + 抽样人工核对，不必手工录入 300 只。

### 2. 法术：319 收录 / 约 23 个机械化
目录、中文名、中文正文都齐了，但战斗内自动结算的只有 23 个。未机械化的法术"只显示规则文字"，玩家施放时 DM 得完全手动。两个建议：

- **半自动中间态**：对未机械化法术提供"自动扣法术位 + 自动掷骰（按目录里的骰子公式）+ 效果 DM 手动"的通道。法术目录里已经有环级和描述，扣位和掷骰是通用的，这一层能覆盖 80% 的手动痛苦，成本远低于逐个机械化。
- **按使用频率排优先级**：实际团里高频法术很集中——识破魔法/解除魔法、隐形术、迷雾术、飞行术、加速/减速、反制法术（需要反应中断，你们的 Interrupt 框架已经具备）、次级复原、复生术。建议照实战频率而不是环级顺序推进。

### 3. 通用规则系统缺口（按实战出现频率排序）
1. **突袭（Surprise）**：每次伏击遭遇都会用到，路线图多处标注"等待通用突袭"（野性直觉、刺客型玩法全被卡）。战斗开始时 DM 标记谁被突袭、首轮跳过即可，成本不高。
2. **坠落伤害**：每 10 尺 1d6，上限 20d6，落地倒地。地图已有海拔（elevationFeet），差临门一脚。被斥力魔爆推下悬崖是最经典的场景，现在只能 DM 手动。
3. **跳跃/攀爬/游泳**：跳远=力量值尺数、攀爬/游泳半速。几何系统已有高度，运动健将、轻身坠等特性都在等它。
4. **同调（Attunement）**：魔法物品已有雏形（`magicItems.ts`），但 SRD 的"最多同调 3 件、短休同调"规则如果缺失，魔法物品发下去就会失控。
5. **兼职（Multiclassing）**：SRD 5.1 含完整兼职规则（属性门槛、法术位合并表）。长期战役 8 级往后需求会集中爆发。数据模型现在是单 class 字段的话，越晚改越痛。
6. **特殊感官**：盲视/颤动感知/真视——已在路线图，怪物目录扩充后会变成硬依赖（黑暗中的黑布丁、隐形的隐形追猎者）。

## 二、跑团流程功能缺失（"跑团桌"而不只是"战斗桌"）

### 1. 游戏内文字聊天 ⭐
目前没有任何聊天系统。远程跑团这是刚需，不是锦上添花：

- IC（角色内）/OOC（角色外）分频道；
- **玩家私聊 DM**（传纸条——玩家想偷东西、察觉到队友没察觉的东西）；
- `/roll 2d6+3` 行内掷骰指令，结果进战斗日志同一条时间线；
- DM 以 NPC 名义发言（选一个 NPC 头像代言）。

基础版（公共频道 + 私聊 DM + /roll）复用现有 SSE 和共享资源框架，工作量可控。

### 2. 讲义与手记（Handouts / Journal）⭐
- DM 向指定玩家（或全体）**分发图片/文本线索**：一封信、一张藏宝图、一个符号。图片通道（`putSharedImage`）已经有了，缺的是"讲义"资源类型 + 可见性控制 + 玩家端提醒。
- **战役日志**：每次团务的剧情记录（DM 写或自动聚合当日战斗摘要），下次开团前"前情提要"。
- 角色笔记已有，但缺**队伍共享笔记**（任务清单、线索板）。

### 3. 遭遇构建器
DM 侧最常见的准备工作：按队伍等级和人数算 XP 预算（简单/中等/困难/致命），从怪物目录拖怪进遭遇，看实时难度，**预存遭遇一键投放到地图**（现在得开战时现摆 Token）。附带解决"多组遭遇提前准备"的需求。数据（XP by CR、难度阈值表）都在 SRD 里。

### 4. 群体检定
"全队做感知检定"是每小时都会发生的事。现在只能逐个走事务。建议：DM 选检定类型和 DC → 全体玩家端弹出掷骰 → 结果汇总面板（谁过谁没过、被动值兜底）。Interrupt 框架已支持多端询问，主要是做一个批量入口和汇总 UI。

### 5. 游戏内时间与光源
- 游戏内日期/时刻推进（长休 24 小时一次的限制、神迹七日冷却已经在按日推进，说明底层有"天"的概念，缺的是显式的时间面板）；
- 火把/提灯燃烧时长、非战斗专注法术的分钟级到期提醒；
- 光源系统已经很完善，差的只是"时间流逝让它熄灭"。

### 6. 地图桌面细节
- **Ping/聚焦**：玩家双击地图产生波纹标记，DM 可拉全员视角到某处。远程跑团里"看这里"没有 ping 就只能语音描述坐标。
- **DM 画笔标注**：临时箭头/圈选（战术讨论），区别于永久的几何/迷雾。
- **回合计时器**（可选开关）：治疗拖延症。
- **观战席位**：现在只有 DM + 8 玩家，加一个只读 spectator 角色成本低（投影逻辑照玩家走，去掉写权限）。

### 7. 安全工具
线上跑团社区标配、实现成本极低：X 卡（任意玩家匿名点击 → 全员提示跳过当前内容）、休息暂停按钮。做了对社区口碑很有用。

## 三、产品与工程层面的问题

### 1. 远程联机的部署故事缺失 ⭐
共享服务跑在本机 5273，这决定了它目前只能"同一局域网跑团"或 DM 自己折腾内网穿透。而文字聊天、讲义这些功能的价值都建立在远程场景上。需要一份明确的部署路径：

- 短期：文档化 Tailscale/frp 等穿透方案 + DM 端一键检测公网可达性；
- 中期：官方 Docker 镜像 + HTTPS 反代说明（现在裸 HTTP，房间密码虽是 scrypt，但会话令牌明文传输）；
- 账号系统已经抽象成"可替换为云端提供者"（`accountApi`），方向是对的。

### 2. `MapsPage.tsx` 约 1.5 万行，是最大的工程风险
前三轮审查发现的问题（快照覆盖回滚、闸门拦死基础动作、探索过滤竞态）全部聚集在这个文件，不是巧合——状态耦合度已经超出可审查范围。建议按"动作处理循环 / 各面板 / 迷雾与几何 / 结算流程"拆成独立模块，每拆一块补一层单测。不拆的话，后续每个新功能都会继续往里叠，缺陷率会持续走高。

### 3. 新手引导缺失
功能密度已经很高（迷雾、几何、三种结算模式、插件工坊、房间恢复码），但没有任何引导。一个新 DM 面对空白战役总览不知道从哪开始。建议：

- 首次进入的检查清单式引导（建房间 → 传地图 → 摆 Token → 邀请玩家）;
- 内置一个 5 分钟示例战役（一张小地图 + 4 个预生成角色 + 3 只哥布林），让新团第一晚就能开打；
- 各空状态页给"下一步"指引而不是空白。

### 4. 移动端/平板不可用
玩家端用手机看角色卡、掷骰是普遍场景。不必让手机跑地图，但**角色卡 + 掷骰 + 聊天 + 自己回合的行动面板**这个玩家子集值得做响应式。

### 5. 角色卡导出/打印
PDF 或图片导出。线下混合团（DM 用投屏、玩家用纸卡）和备份心理都需要。角色数据已完全结构化，是纯输出层工作。

### 6. 规则速查
法术书已有；缺**状态/动作/掩护/视觉规则速查**。战斗中点状态图标应能看到完整规则文字（数据在 `conditions.ts` 里已经有了，主要是 UI 入口）。

### 7. 性能预算未验证
视野多边形按 viewer × 帧计算、探索多边形无上限追加、80→160 条战斗日志全量同步。建议做一次基准场景压测：100×100 地图、40 Token、8 视野源、双小时战斗的探索数据量，提前发现天花板。

### 8. 技术债提醒
- 第三轮代码审查的 36 项（8 高危）尚未修复，其中 H2（HP 静默回滚）、H1（无限召唤）、M6（sourceMode 信任）建议本周处理；
- 路线图自述"旧事务实现的物理删除仍须继续"——旧 AP 代码残留每多留一天，就多一分被新代码误引用的风险；
- `characters` 资源整体玩家可写（无按成员字段隔离）是多个已发现问题的共同根源（专注伪造、HP 竞态），值得做一次统一的"玩家可写字段白名单"改造，一劳永逸。

## 四、优先级建议

**P0 — 决定"能不能跑完整战役"（建议 1~2 个迭代内）**
1. 修复第三轮审查的 8 个高危缺陷
2. 怪物目录批量导入 + 自定义怪物编辑器
3. 突袭轮、坠落伤害（两个小而高频的规则）
4. 文字聊天基础版（公共 + 私聊 DM + /roll）
5. 未机械化法术的"扣位 + 掷骰"半自动通道

**P1 — 决定"跑得舒不舒服"**
6. 讲义分发 + 战役日志
7. 群体检定
8. 遭遇构建器 + XP 预算
9. 游戏内时间/光源燃烧
10. Ping/DM 标注/观战席位
11. 远程部署方案文档化 + Docker 镜像
12. MapsPage 拆分（与新功能并行推进）

**P2 — 决定"愿不愿意推荐给别的团"**
13. 新手引导 + 示例战役
14. 移动端玩家子集
15. 兼职、同调、特殊感官
16. 角色卡 PDF 导出、规则速查完善
17. 安全工具、回合计时器、音频氛围

## 五、一句话总结

这个项目的战斗引擎深度（权威结算、防作弊、插件生态、恢复能力）已经是"发烧级"，但一个真实团的留存取决于木桶短板：**怪不够用、非战斗环节没工具、远程玩不了**。建议下一阶段把工程力量从"继续加深战斗自动化"转向"补齐跑团闭环"——先让一个普通团能用它无痛跑完一个完整模组，再回头继续机械化长尾法术。
