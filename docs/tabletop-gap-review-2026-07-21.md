# DNDSTARS-5E 跑团工具缺口审查（2026-07-21）

审查基线：`main@84c6364` 加本轮 SRD 内容来源改动。验证结果：TypeScript／Vite 生产构建通过，157 个单元测试文件共 1159 项全部通过，ESLint ratchet 为 0 error／0 warning。

## 已经具备的跑团主链

当前项目已经不是“只有人物卡和战斗 Demo”：房间创建／加入、账号恢复码与角色库、DM／玩家／观战席位、跨端房间同步、聊天／私聊、讲义、战役日志、共享笔记、群体检定、地图与 Token、战争迷雾、动态视野、墙／门／窗／障碍物、光照、Ping／画笔、先攻、三种结算模式、骰子确认与 Interrupt、状态生命周期、战斗日志、战斗统计、XP 分配、角色卡、12 个 SRD 职业、兼职、法术书、物品栏、同调、怪物目录、怪物工坊、遭遇构建器、插件沙箱和备份恢复都已经存在。

因此下一阶段不应再重复做这些入口，而应收敛内容、规则深度、生产部署和长期可维护性。

## P0：公开测试或商业发布前必须完成

### 1. SRD 中文发布数据尚未完成独立审校

- 法术目录有 319 项；旧 PHB 来源运行正文已经删除，未审校条目只显示目录信息。
- 魔法物品目录有 240 项；旧机器翻译正文已经删除，未审校条目只显示目录信息。
- 本轮已删除 PHB 提取器和 Lingva 生成链，新增官方英文 SRD 工作表＋人工审校门禁；在 319／319 和 240／240 全部完成前，不能把当前构建标记为内容发布就绪。

验收标准：每个条目都有稳定 SRD ID、官方英文名称／页码、中文正文、审校人和审校日期；`--emit` 全量通过；应用内与 `ATTRIBUTION.md` 同时保留 WotC 指定的 CC BY 4.0 署名。

### 2. 高价值跨端 E2E 仍不足

现有 20 个 E2E 场景覆盖房间、角色、插件、地图几何、视野、库存、XP、群体检定、时间等，但没有覆盖完整的“角色准备法术 → 玩家施法 → DM 骰子确认／Interrupt → 多端 ACK → 刷新恢复”，也没有覆盖传奇抗性、持续区域跨回合和怪物复杂能力降级。

建议至少补四条发布门禁 E2E：普通法术攻击／豁免、反应法术、持续区域、DM 裁定法术。每条都要验证重复提交不会二次扣法术位或重复伤害。

### 3. 账号角色库仍是单机共享服务，不是真正云服务

当前账号与角色库持久化到 DM／共享服务机器的文件目录，恢复码和跨设备逻辑已经具备，但 DM 主机离线时仍不能作为独立云角色库使用。若目标只是“DM 开机才能开团”的自托管工具，这不是阻塞；若要网页端与 Steam 客户端共享账号和角色，则仍需中央身份服务、数据库、对象存储、TLS、备份、配额和迁移机制。

## P1：直接影响常规跑团完整度

### 1. 怪物目录完整，但复杂能力仍大量依赖 DM

334 个 SRD 怪物已收录；集群战术、多重攻击、传奇抗性已有 Headless。以下通用能力仍明确标记为 `dm-adjudication`：传奇动作、巢穴动作、再生、群集半血变化、充能动作、怪物施法、变形，以及飞行／水下环境规则。

建议按实战频率做通用事务，而不是逐怪硬编码：

1. `RechargeResource`（回合开始掷 d6、5–6 恢复等）。
2. `LegendaryActionWindow`（其他生物回合结束触发、点数池、回合开始恢复）。
3. `RegenerationRule`（回合开始恢复、特定伤害关闭）。
4. `MonsterSpellcastingProfile`（法术位／每日次数／先天施法复用核心法术事务）。
5. `SwarmDamageProfile` 与变形生命池。

### 2. 法术目录 319 项，完整 Headless 只有 63 项

剩余法术能通过 `dm-adjudication` 正常消费动作与法术位，因此“能跑团”，但自动化深度仍明显不足。下一批不应单纯追求数量，优先接入高频且能复用通用底座的类型：

- 控制与行动：命令术、睡眠术、缓慢术、加速术。
- 独立实体：灵体武器及多只召唤物共享先攻。
- 传送与飞行：迷踪步、飞行术、任意门，依赖合法落点和高度。
- 形态：变形术与野兽／原形快照。
- 法术交互：解除魔法、法术反制嵌套、墙类法术与效果线。
- 探索法术保留结构化 DM 裁定即可，不需要为了数字伪造自动化。

### 3. 库存仍缺长期战役常用规则

基础装备、分发／转交／丢弃／使用、实例资源、黎明恢复、同调与部分 Headless 物品已完成。尚缺：负重／容重、容器嵌套、货币账本、弹药消耗、鉴定／未鉴定状态，以及多数魔法物品的充能施法、抗性、属性设值、召唤和特殊命中效果。

建议先做通用 `ItemEffectTransaction`：实例资源 → 目标／法术 ID → 使用时机 → Interrupt → 原子提交；魔杖、法杖、戒指和药水都复用同一入口，装备正文中的法术必须只保存结构化 spell ID，显示名从 `spellNamesZh.ts` 解析。

### 4. 地图仍是 2D 为主，立体和环境规则不完整

当前已有海拔字段、墙体高度、视线／移动／效果线、掩护与坠落，但尚缺地表高度多边形、自动悬崖判定、完整飞行／悬停、垂直墙面／液面移动、水下战斗、魔法黑暗、玩家可操作灯具，以及幻象／以太／连续表面等感知语义。

### 5. 探索与资源消耗仍偏手动

战役时间、长休限制、光源过期和群体检定已有。旅行步调、食物／水、负重、迷路、天气、野外遭遇、窒息和追逐仍没有统一探索事务。建议先做“旅行日”事务，把路程、步调、口粮、水、疲劳／力竭和随机遭遇挂到权威战役时钟上。

## P2：提升桌面体验与 DM 效率

- 建立独立规则资料库页面：怪物、物品、状态、动作与法术统一搜索，避免必须先进入地图或分发面板才能查资料。
- 增加常用骰式／动作快捷栏和 DM 宏，但宏只能组合已有 capability，不能写 Store。
- 地图／场景文件夹、场景预加载、批量 Token 与遭遇模板复用。
- 可选音频播放列表、环境音和音量同步；语音／视频可以继续交给 Discord 等外部工具，不必成为核心阻塞。
- 日志筛选、导出、回合摘要和“从日志跳到 Token／事务”。

## 架构与性能风险

### MapsPage 继续膨胀

`MapsPage.tsx` 当前约 15,464 行、759 KB；此前拆出的模块已经被新功能增长抵消。下一轮应继续按“行动准备／权威提交／中断协调／地图投影／面板状态”拆分，并禁止新增大段 resolver 到页面组件。每次拆分应保留事务级单测和一条 E2E。

### 首屏包过大

生产构建当前主包约 3.06 MB（gzip 877 KB），怪物目录 chunk 约 745 KB（gzip 101 KB），骰子 chunk 约 550 KB（gzip 144 KB）。怪物已独立分包，但法术正文、魔法物品正文、地图与大面板仍进入主包。建议按路由和资料库动态加载，地图、角色、法术、通讯与设置分别成 chunk；旧运行译文替换后再测一次体积预算。

6. 再扩法术 Headless、立体移动与旅行探索。
