# 战役进阶数据 V3

“进阶数据”由 DM 端订阅成功提交的 D&D 5e Headless 事务生成。它不解析日志文本，也不接受玩家端自行上报的伤害、治疗或贡献值。底层 `combat-statistics` 名称为兼容旧存档保留，旧版“战斗统计”界面和不透明的总贡献分已经移除。

## 统计口径

- 输出与承伤按目标实际损失的生命值和临时生命值计算，过量伤害不计入输出。
- 治疗只记录实际恢复量。把其他单位从 0 HP 恢复到正数时，治疗者同时获得一次“救援”。
- 控制记录对敌对单位成功施加的标准状态，以及驱散亡灵等结构化控制事件。
- 击倒记录目标从正生命降至 0 HP；没有死亡豁免且没有待结算亡灵坚韧的目标同时记为击杀。
- 每回合平均伤害/治疗使用实际进入的角色回合数作为分母。
- 天然 d20 分布记录 Headless 事件最终采用的骰面。非战斗范围还会加入群体检定，以及有明确角色身份的聊天 `/roll`；被动值和手动实体骰不会被推测记录。
- 攻击命中率、暴击率、豁免成功率与专注维持率仅在存在对应样本时计算。

## 进攻与防御/支援指数

指数是同阵营内的相对占比，不是 D&D 5e 规则数值：

- 进攻指数等权统计有效伤害、命中、控制、击倒/击杀四个维度。
- 防御/支援指数等权统计有效治疗与临时生命、减伤、救援、成功豁免四个维度。
- 没有样本的维度不会进入分母；有样本时，同队成员的指数总和约为 100%。

这种口径用于复盘角色在不同维度的参与度，不替代 DM 对探索、叙事、站位、战术决策或角色扮演贡献的判断。

## 权威、同步与迁移

- Headless 观察器只在根事务结束后触发，不改变结算结果。
- 每次事务生成确定性 receipt；同一输入状态、动作和事件被重放时不会重复计数。
- `combat-statistics` 是 DM 写入的房间共享资源，客户端与服务端都执行严格 schema 校验，损坏的 V3 数据会 fail closed。
- V1/V2 存档会迁移到 V3；旧存档缺少的回合数与 d20 分布从零开始，不伪造历史样本。
- 房间保留最近 24 场战斗，每场最多保留 4096 个 receipt。
